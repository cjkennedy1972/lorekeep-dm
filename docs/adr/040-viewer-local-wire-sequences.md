# ADR-040: Viewer-local wire sequences for concealed events

Status: Proposed · Date: 2026-10-31 · Owner: Sage · Work item: card `44b0fcbc` (board `lorekeep-dm`)

Append-only: this ADR adds a wire-delivery contract. It does not edit ADR-003, ADR-010, ADR-029, ADR-033, ADR-034, or ADR-036.

## Context

The canonical room event log uses one contiguous, persisted `seq` per event. `Room` advances `this.seq` to the last stored event and broadcasts `CombatEvents` after applying a viewer-specific projection. Hidden events are omitted from a viewer's projected payload, but the frame still carries the global room head. Thus a viewer can infer how many committed events were withheld from the difference between visible frame sequences. `TurnResolved` is already excluded from client payloads because its filtered `eventIds` disclose hidden-event count, but its global sequence gap remains (the comment in `Room.announceCombat` explicitly records this residual). The same issue applies to any projected event batch, not just `TurnResolved`.

The client contract makes the gap operationally visible: `apps/web/src/room/reducer.ts` treats a non-contiguous sequence as possible lost delivery and requests resynchronization. Therefore simply allowing gaps or sending global cursors under a new name is not sufficient. A frame's sequence currently serves two distinct purposes: canonical event-log position for the server and contiguous delivery position for the client. Those positions must be separated.

Bastion's review of PR #431 demonstrated a hidden area-resolution case with 9 persisted events when the hidden creature was in the blast and 7 when it was absent, although the acting viewer's projected event bodies matched. Its later review noted that repeated area-aim probes could localize a hidden creature from sequence deltas. PR #432's reviews repeatedly excluded this card; one probe also observed differing sequence values for a hidden-reactor movement. These are residual channels, not regressions introduced by those PRs.

Relevant contracts: ADR-003 makes the server event log append-only and replay-authoritative; ADR-010 assigns sequence-gap recovery to the client; ADR-029 establishes the serialized Room; ADR-034 requires per-viewer omission of hidden entities/events while preserving the canonical log and specifies coalesced hidden-reactor movement; ADR-036 treats reconnect StateSync as authoritative and keeps private projections separate. The narrow invariant is: **for two executions with identical viewer-visible logical updates, the ordered sequenced-frame list (frame type, count, order, and cursor values) is identical.** This closes count and position leakage through sequence metadata and frame boundaries; it does not claim to hide delivery timing, transport batching, payload-size differences, or other side channels listed below.

## Decision

Keep the canonical persisted sequence (`eventSeq`, currently stored `seq`) global, contiguous, and authoritative for event order, snapshots, replay, rewind, and internal event references. Introduce a separate **viewer-local wire sequence** for each authenticated seat delivery stream. Within that stream it advances only for sequenced, viewer-visible logical updates; it is dense, strictly increasing, and never derived directly from the global event number. Internal event ranges may contain multiple canonical events; hidden events do not consume a viewer cursor.

**Sequenced-frame inventory and cursor source.** Every outbound frame with a `seq` field is covered, regardless of its feature or call site. The current `ServerMessage` discriminants are all in scope: `ChatMessage`, `ChatHistory`, `NarrationHistory`, `ActionQueued`, `RoundOpened`, `RoundActionAccepted`, `RoundActionQueued`, `RoundActionEdited`, `RoundActionWithdrawn`, `RoundClosing`, `RoundResolved`, `RoundCompleted`, `RoundClosedEmpty`, `RoundTimerConfigured`, `TurnTimerConfigured`, `SeatRevoked`, `SeatCharacterBound`, `SeatCharacterReleased`, `SeatTakenOver`, `HostTransferred`, `HostSeatChanged`, `LateJoinRequested`, `LateJoinDenied`, `TableEnded`, `ChatMuteChanged`, `LateJoinApproved`, `SeatClaimRequested`, `SeatClaimApproved`, `SeatClaimDenied`, `SeatClaimExpired`, `SeatAuthenticated`, `SeatClaimPending`, `SeatResumeChallenge`, `RestVoteOpened`, `RestVoteCastNotice`, `RestVoteClosed`, `RestApplied`, `ActionWithdrawn`, `ClarificationRequested`, `TurnThinking`, `RollEvent`, `NarrationChunk`, `NarrationCompleted`, `TurnReverted`, `ToolRejected`, `ContentTierChanged`, `SafetyFlag`, `DeathSaveRequired`, `TpkChoiceRequired`, `SpotlightPrompt`, `StateSync`, `SeatPrivateRoundSync`, `SeatCharacterBoundPrivate`, `CombatTracker`, `ReactionPrompt`, `ReactionPromptOpen`, `CombatOptions`, `CombatEvents`, `CombatEnded`, `PresenceChanged`, and `Error`. `TurnResolved` is a canonical event within delivery, not a standalone frame discriminant. This list must be kept in sync with `ServerMessageSchema`; future sequenced discriminants are covered automatically. For every concrete `seq: this.seq`, `seq: room.seq`, helper-constructor, and forwarded-event site, the implementation audit must classify it as (a) a sequenced logical update, or (b) a non-advancing checkpoint/no-change frame. For (a), source is that recipient's stream cursor; for (b), source is that same cursor and it does not advance. No sequenced frame may carry the global head. Unsequenced ephemeral messages remain outside gap detection. This inventory is intentionally an acceptance requirement, not an assertion that a partial source grep is exhaustive.

A **logical update** and its frame boundary are defined by viewer-visible state, not by canonical commit count. Before sending sequenced frames, the server MUST coalesce/split updates so that hidden-only events, hidden commit splitting, and hidden prompts cannot change the number, type, or order of sequenced frames observed by a viewer whose visible logical updates are otherwise identical. In particular, hidden events that cause reaction-open/resolve, narration, or `TurnResolved` commits must not introduce or split a viewer frame. Per-commit cursors alone do not satisfy this rule. Assign one increment per viewer-visible logical update after projection/coalescing; emit no sequence-advancing frame for hidden-only commits. StateSync is a checkpoint, not an event replay.

The web reducer MUST apply contiguous-gap detection to every sequenced frame type, including all combat frames (`CombatTracker`, `ReactionPrompt`, `ReactionPromptOpen`, `CombatOptions`, `CombatEvents`, `CombatEnded`, `DeathSaveRequired`, `TpkChoiceRequired`) and room-state frames. A missing next cursor sets `needsResync` and requests resync; duplicate/older frames remain ignored. Unsequenced ephemeral frames are not covered. A checkpoint resets the baseline only after its authoritative projection is applied.

The server retains canonical global event id/sequence internally. Viewer-local sequence is delivery metadata, not an event identifier, ordering source, or persistence key. Cursors **never drive replay**: reconnect/resync sends nothing only when the authenticated viewer cursor equals that viewer's current stream head; any mismatch, absent/unverifiable cursor, or epoch mismatch sends authoritative StateSync. The reconnect and late-join `StateSync` gates and the coupled `sendNarrationHistory` gates MUST compare against the bound viewer stream head, never `this.seq`/global head. Narration history is included only under its existing visibility policy and must not be gated by global-head comparison.

If replay is added in the future, it must use commit-time visibility, never re-project historical events using current controller/seat state. Persist an immutable commit-time delivery-eligibility decision with the canonical event/commit sufficient to reproduce who could receive it. If that decision or replay material is unavailable or inconsistent, fall back to StateSync; never infer visibility from current control state. Do not add a per-viewer payload history or global-to-viewer cursor map as part of this decision.

A viewer stream is keyed by server-bound `(seatId, bindingEpoch)`, not a client-supplied seat id, account display identity, socket, or client cursor. The server derives seat identity from authenticated binding. Reconnect preserves the cursor only within the same epoch. Revocation followed by reassignment, resume-token rollback, or any change in seat binding increments the epoch, invalidates the old cursor, and requires StateSync to establish a new baseline. No client input may select another stream or roll its cursor backward. Cursor updates and event commits are serialized by the Room mailbox so no two frames race or reorder a stream.

### Persistence and recovery contract

Persist or checkpoint the latest viewer-local cursor with the Room's durable head (one small value per active seat) in the same transactional/serialized progression as canonical events. Do not persist a per-viewer copy of event payloads, duplicate event histories, or a global-to-viewer mapping for every event. The event store continues to be queried by canonical `eventSeq`; current delivery projects by recipient using the commit-time visibility decision. If a cursor checkpoint is absent, malformed, or inconsistent on recovery, do not guess from the global head: send StateSync and establish a safe viewer-local baseline. Rewind appends canonical events as ADR-003 requires; it never decrements or reuses a viewer cursor. Account deletion/redaction retains its existing event semantics.

StateSync and all messages currently using `room.seq` as a client cursor must be audited. Frames without a visible state change may carry the current viewer cursor but must not advance it. One committed update delivered to multiple seats may have different wire cursors while referring internally to the same canonical event range. No client-visible payload may include `eventSeq`, canonical event ids, hidden-event count, or a global head cursor.

### Compatibility and rollout

Use a **single-step cutover**, shipping server and web together. Do not add protocol negotiation, adoption tracking, or a dual-protocol window: the project is pre-release (`apps/*/package.json` is `0.0.0`; the architecture beta gate is week 23+), and no wire capability/version negotiation exists. Keeping a legacy global-sequence mode would leave the disclosure open for an unbounded period. A dense per-viewer sequence remains compatible with the existing client's `lastSeq + 1` rule; frames with `seq <= lastSeq` remain ignored. A stale or mismatched cursor receives StateSync. Add a compatibility test for this behavior rather than a rollout window. An old client that cannot safely consume the single-step contract must be refreshed/upgraded and receive authoritative StateSync; it must never silently receive global sequence numbers after cutover.

On first viewer-local connection, send StateSync with that seat-epoch cursor baseline. Reconnect with missing, old, corrupt, or wrong-epoch cursor receives StateSync; no historical event-row backfill is needed. Preserve canonical `eventSeq` in the database and all internal joins/snapshots.

### Required tests (implementation acceptance; not part of this docs-only change)

- **Sequenced-frame inventory and probe:** enumerate the actual sequenced discriminants and cursor source from every Room/gateway send path, including all B1-listed frames and reconnect StateSync. Run the same deterministic Room/websocket area attack/aim twice with pinned dice/RNG and identical visible logical outcomes. Capture each viewer's full ordered frame list as `(type, count, seq, body)`; assert byte-identical visible lists, including frame count and order, while canonical persisted counts/global IDs differ. Cover `CombatTracker`, hidden-reactor `ReactionPromptOpen` to a non-controller, all sequenced room/game frames, and StateSync on reconnect mid-turn. Repeat candidate cells. Assert timing is excluded (or separately measured); do not infer timing equality from sequence equality. The current `main` failure must be asserted with a specific signature (e.g. `CombatTracker seq delta differs` or a named frame-count/order mismatch), not generic `seq differs`; retain failing-first evidence. Add a visible-creature blast positive control with a differing visible outcome and corresponding allowed frame difference. Run both controller and non-controller seats; prove independent streams.
- **Frame-boundary invariance:** vary only hidden-event count and hidden commit splitting (including reaction prompt open/resolve, TurnResolved write, and narration). With identical viewer-visible logical updates, frame type/count/order and projected bodies must remain identical. A cursor-per-commit implementation alone must fail this test.
- **Reducer gap correctness:** drop each family of sequenced frame, including every combat type listed in the Decision; `needsResync` is set and exactly one resync is requested. A hidden-only commit creates no cursor gap/resync; duplicates and out-of-order frames are ignored. Checkpoint applies projection then resets baseline.
- **Reconnect/restart and gates:** verify equality with the bound viewer stream head is the sole no-send fast path. Exercise late join, reconnect and resync where hidden-only canonical events committed while disconnected: StateSync/narration-history behavior must not reveal that global delta. Stale, absent, corrupt, or wrong-epoch cursor gets authoritative StateSync. Cursors never initiate replay.
- **Per-seat isolation / epochs:** simultaneous seats get independent dense streams; client-supplied seat ids/cursors cannot choose a stream. Revocation/reassignment, binding-epoch change, and resume-token rollback start a new epoch and force StateSync; old cursor cannot be resumed.
- **Commit-time visibility for future replay:** test that a hypothetical replay never makes an event visible because controller state changed after commit. If immutable commit-time eligibility is absent, verify replay falls back to StateSync.
- **Ordering and latency:** concurrent commits across a 2–6-seat room yield monotonic per-seat delivery in canonical order; instrumentation verifies added projection/cursor work keeps existing end-to-end multi-seat synchronization budget at or below 1 s under the project's agreed load profile.
- **Single-cutover compatibility:** compatibility test exercises existing `lastSeq + 1` clients against dense per-viewer sequences, ignores `seq <= lastSeq`, and recovers stale/mismatched cursors by StateSync. No legacy global-seq serving mode or negotiation window remains.
- **Canonical semantics and projection regression:** canonical event replay, snapshots, rewind, redaction, and internal references continue using global event sequence. Add a regression asserting `clientGameState` strips `turnNarrationEvents`, `turnNarrationEventIds`, and `narrationAttempts` from `combatRoom`; `turnNarrationEventIds` must never expose canonical seq values.

## Consequences

Viewer clients retain the gap-detection guarantee from ADR-010 without receiving a numeric proxy for withheld event volume. Server persistence remains canonical and append-only; wire ordering is explicitly a projection of that history. The change adds a small per-seat, per-binding-epoch recovery cursor and requires a coordinated single-step server/web cutover. The narrow invariant covers sequence and sequenced-frame structure, not delivery timing or other public game side channels. The design does not hide that visible, legitimately disclosed events occurred, nor does it equalize frame timing or total payload size where those are already visible through public game effects.

## Size and scope

**Size: M (cross-cutting protocol/state migration, no event-row rewrite).** Expected implementation spans schema/handshake, Room delivery and recovery, gateway, web reducer/client, and focused server/web tests. No production behavior changes are included in this ADR PR.

**Explicitly out of scope:** changing canonical database event sequence or snapshot keys; redacting or rewriting historical events; suppressing game mechanics, rolls, visible outcomes, or event timing; fixing the separate information channels from movement previews/rejections, damage, narration, public reveals, or unpadded message timing; encrypting event cursors; changing chat/private-round projections; solving hidden-entity authorization or visibility rules; implementing this ADR in the docs-only PR. This ADR covers numeric event-count leakage from sequence/cursor metadata, not all side channels.
