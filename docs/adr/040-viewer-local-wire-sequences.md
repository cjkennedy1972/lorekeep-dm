# ADR-040: Viewer-local wire sequences for concealed events

Status: Proposed · Date: 2026-10-31 · Owner: Sage · Work item: card `44b0fcbc` (board `lorekeep-dm`)

Append-only: this ADR adds a wire-delivery contract. It does not edit ADR-003, ADR-010, ADR-029, ADR-033, ADR-034, or ADR-036.

## Context

The canonical room event log uses one contiguous persisted `seq` per event. `Room` advances its global head and broadcasts projections, but hidden events omitted from a viewer payload can still affect the global sequence carried by frames. A viewer can therefore infer withheld event count from sequence deltas. The client currently uses contiguous sequences for lost-delivery recovery, so simply permitting gaps or renaming the global cursor is not sufficient: canonical event order and client delivery position must be separate.

The invariant is: for two executions with identical viewer-visible logical updates, each viewer's ordered sequenced-frame list (type, count, order, and cursor values) is identical. This includes frame boundaries. It does not claim to hide timing, transport batching, payload-size, or other explicitly excluded channels.

## Decision

Keep the canonical event sequence global, contiguous, and authoritative for persistence, replay, rewind, snapshots, and internal references. Introduce a dense viewer-local cursor for each server-bound seat stream. A cursor advances only for a viewer-visible logical update, after projection and coalescing; it is never derived from a canonical event number and never drives replay.

### Normative wire and classification rules

Every outbound application frame is considered in the confidentiality comparison, sequenced or not. The single-step server/schema/web cutover has three mutually exclusive classes:

- **(a) Advancing logical updates.** Each transmitted viewer-visible logical update advances that seat stream by exactly one. This includes persisted `PresenceChanged` and `SeatTakenOver` (including same-binding socket takeover), `ChatMessage`, combat/round/turn/action updates, visible room/seat changes, narration and prompts, and other committed projected updates. The exhaustive discriminant/site inventory is an implementation acceptance item below, not a second list here. `TurnResolved` is an event within projected delivery, not a standalone frame discriminant.
- **(b) Current-cursor replies.** Request-scoped direct replies and private/handshake/error messages carry the current viewer cursor without advancing it. This class includes `StateSync`, `ChatHistory`, `NarrationHistory`, `SeatPrivateRoundSync`, `CombatOptions`, `Error`, `SeatAuthenticated`, `SeatClaimPending`, and `SeatCharacterBoundPrivate`. Broadcast `Error`, if any, is also non-advancing. `SeatTakenOver` is class (a), not class (b). A pre-baseline `SeatResumeChallenge` remains cursor-less and never initializes or advances a stream.
- **(c) Unsequenced frames.** Frames with no cursor are cursor-less. Their count and timing can still correlate with hidden activity; they are not exempt from frame-boundary confidentiality. The implementation audit must identify hidden-triggerable ephemeral frames and either coalesce them to visible-update boundaries or name the specific necessary out-of-scope residual and its observable information.

Each server-message discriminant MUST appear in exactly one of (a), (b), or (c); no discriminant is both advancing and non-advancing. The implementation acceptance audit verifies this partition against the schema. `CombatOptions` is class (b) only: it is a request-scoped direct reply carrying the current cursor, never an advancing update.

No message produced by `Room` may contain `seq`, canonical `event.seq`, `this.seq`, `room.seq`, or a stored/global sequence. Enforce this at the type level: Room-produced message types omit `seq`; only the per-seat transmit layer may add the schema's `seq`, sourced from that seat stream. The per-seat ordered send queue attaches each commit-assigned cursor at transmit dequeue, not enqueue, so wire order equals cursor order. For chat, the commit-time recipient plan is authoritative: membership is revalidated with the shared eligibility predicate inside the canonical transaction before the cursor UPSERT, and dequeue does not reclassify eligibility. An update rejected by that transaction consumes no cursor. If an update eligible at commit is later not delivered because membership changes after commit, the socket disappears, or a send race occurs, its cursor remains consumed; the next received cursor has a gap and normal resync/StateSync repairs the client. This is the specified post-commit send-loss case, not a skipped cursor or a dequeue-time eligibility decision.

The existing schema requires `seq` on `PresenceChanged` and `Error`; the cutover changes it so `PresenceChanged` is class (a) with the viewer cursor and `Error` is class (b) with the current viewer cursor. `StateSyncAck` is currently strict `{ seq }`; the cutover changes it to strict `{ bindingEpoch, generation, seq }`. `StateSync` carries the same binding epoch and generation plus that recipient's viewer cursor. These are schema changes in the implementation scope, not optional compatibility behavior. The pre-stream `SeatResumeChallenge` currently serialized with `seq: 0` becomes explicitly cursor-less in the schema; it never enters cursor logic or satisfies an acknowledgement.

### Projection, broadcasts, and chat

The commit-time recipient set is computed before cursor advancement from the same Room state object being written under its single-writer queue. A single shared chat-eligibility predicate is used for recipient computation and the per-socket `hasCurrentSeat` check; it uses the same membership source and explicitly requires `status = 'active'`. Membership is re-verified in the canonical commit transaction, which is authoritative for cursor assignment. A later failed `hasCurrentSeat`/sendability check drops an already-committed frame as post-commit delivery loss; it does not revoke eligibility or roll back its cursor. `writeChat` and `writeTurn` accept the recipient plan so cursor UPSERTs are applied only to eligible seats whose projected batch is non-empty. Socket presence and spotlight target selection are send-time concerns, not commit-time eligibility inputs.

Projection must return an explicit “no logical update” result. The send path MUST NOT run for that result. A commit whose projection is empty for a recipient emits zero sequenced frames, zero current-cursor broadcast frames (including any broadcast `Error`), and zero unsequenced application frames to that recipient. No Room broadcast (including `StateSync`) may be triggered by or vary with such a commit. Any broadcast keyed to the raw canonical event list must instead be computed per recipient from that recipient's projected batch, or suppressed for recipients whose projection is empty. In particular, combat round-boundary refresh logic must not broadcast based on a raw `TurnStarted` list; it is projection-gated per recipient. State-change broadcasts not caused by canonical commits are permitted only as visible state changes or explicit recipient-specific request/recovery replies, never as a proxy for hidden commit activity.

Every `StateSync`, including presence-return refresh and late-join paths, is built separately per recipient and carries that seat's current cursor/generation/epoch, never the global head. Reconnect/resync and late-join no-send gates compare only against the bound viewer stream head. `StateSyncAck` and `requiredSnapshotSeq`/late-join snapshot bookkeeping likewise use the viewer baseline/head, never global `this.seq`. A stale, missing, wrong-epoch, or wrong-generation acknowledgement cannot unlock a socket or satisfy a snapshot gate; resend authoritative StateSync. The acknowledgement must match the server-bound seat and the exact baseline sent on that socket.

`ChatHistory` entries MUST NOT carry canonical event sequence values. Assign page-local ordinals only after visibility and `ChatMessageSchema` parsing/filtering; the frame itself is class (b) and carries the current viewer cursor. Compute the ChatHistory window and page cap over the same per-viewer eligibility predicate used for chat delivery, so recipient-restricted chat cannot leak through the page size or window. Message content and projection remain out of scope; the entry sequence field and its ordinal semantics are in scope.

### Binding epochs, durable stream record, and recovery

The durable cursor record is a new `seat_streams(session_id, seat_id, binding_epoch, generation, cursor)` table keyed by `(session_id, seat_id)`. It is the durable stream record; there is no assumed durable seat-binding row. `generation` is an opaque 128-bit token generated from a cryptographically secure random source, not an ordered/counting value; create a fresh token on first bind with `binding_epoch = 1` and `cursor = 0`. Advance `binding_epoch` only on an event-sourced bind, release, replace, or revoke of the seat binding, in the same transaction as that binding event. “Replace” means reassignment to a different binding row/account; a same-binding socket takeover, including `SeatTakenOver`, is not a replace and does not bump the epoch. Retain released-seat stream rows so epochs cannot silently reset. Resume-token rotation/rollback tables are not modified and do not change epoch, generation, or cursor.

For each canonical commit, in the same database transaction as canonical event persistence, revalidate membership using the shared active-membership predicate (`status = 'active'`) and issue one `seat_streams` UPSERT per eligible recipient whose projected batch is non-empty, advancing its cursor by the number of coalesced logical updates assigned to it. This transaction's recipient eligibility is definitive for that commit; later membership changes do not undo or skip the committed cursor advancement. A projection-empty recipient gets no UPSERT. Commit-time binding changes update the stream row's binding epoch in that same transaction and start its new binding baseline. Do not checkpoint the cursor separately from events. Publish no in-memory cursor changes or frames if the transaction fails. Send only after commit. On restart, load the durable record. A client cursor behind the durable head receives StateSync, not replay; a crash after commit and before send is repaired through this reconnect StateSync path.

A missing, malformed, mismatched, or corrupt stream record is reinitialized without changing the binding epoch: generate a fresh 128-bit cryptographically random `generation` token (never reuse the previously issued token), set cursor to `0`, and send authoritative StateSync. Do not derive generation from a canonical event sequence, global counter, or an untrusted/corrupt row. The reinitialization UPSERT is committed at subscribe or atomically with the next canonical commit before any new cursor is sent. The client re-baselines only after applying that StateSync. The first advancing frame in the new generation is cursor `1`. If the stored generation/cursor is malformed or its epoch disagrees with the current binding epoch, use the same generation-bump recovery. If the stored `binding_epoch` is higher than the event-sourced binding epoch, treat it as corruption, reinitialize for the current epoch with a fresh random generation token, and emit a structured error log containing the event name only. If recovery cannot be durably confirmed, keep the seat disconnected. A client pair whose `(bindingEpoch, generation)` differs from the current stream is never accepted, even if its numeric cursor equals the head. Binding epoch changes only for bind/release/replace/revoke; recovery changes generation, not epoch. Rewind never decrements or reuses a viewer cursor.

The cursor is a checkpoint only; do not persist per-viewer payload histories or global-to-viewer event maps. Canonical `eventSeq` remains the only event-store lookup key. Future wire replay would require immutable commit-time delivery eligibility persisted with the event; absent or inconsistent replay eligibility falls back to StateSync.

### Reducer contract and current-code note

The implementation must apply one contiguous-cursor check to every class-(a) frame. A missing next cursor marks `needsResync`; the client requests resync; duplicate/older frames are ignored. `StateSync` applies its authoritative projection before establishing the new `(bindingEpoch, generation, cursor)` baseline. `StateSyncAck` echoes that triple. Unsequenced and current-cursor frames do not update the advancing cursor.

Current `apps/web/src/room/reducer.ts` gap checks exist for `PresenceChanged`, `RoundClosing`, and `SeatCharacterReleased`; most combat and other room-patch families currently return without checking `seq`. Current `StateSync` also has a numeric stale-snapshot guard. The implementation must extend contiguous checks to all class-(a) frames and replace that guard with binding-epoch/generation-aware authoritative baseline handling. `SeatResumeChallenge` is never passed to cursor logic.

## Implementation acceptance audit

This checklist is required in the implementation PR; this ADR does not enumerate all current send sites. Attach the audit results and tests to that PR.

- [ ] **Discriminants and all cursor sites:** inventory every server-message discriminant and classify it in exactly one of (a)/(b)/(c). Audit all current Room/gateway `seq` construction, helper/forwarded-event paths, and roughly 93 known sequence-bearing sites. Confirm Room-produced types omit `seq`, no Room builder reads canonical/global/stored seq for the wire, and the per-seat transmit layer is the sole cursor author. Explicitly cover `SeatTakenOver`, the duplicate `SeatTakenOver` in solo-owner recovery, `SpotlightPrompt`, `ChatMessage`, `PresenceChanged`, `Error`, `CombatOptions`, and pre-stream `SeatResumeChallenge`.
- [ ] **All broadcasts and projection-empty behavior:** audit every Room broadcast and roughly 24 broadcast `StateSync` sites, including host tier cap, pause, chat mute, kick, host transfer, end-table/rewind, connection-pause reconciliation, late-join request/approve/deny/cancel/admit, presence return, and combat boundaries. Classify each as an independent visible state change/request reply or gate it on each recipient's non-empty projected batch. The combat round-boundary refresh is driven by the recipient-projected batch, never raw canonical `TurnStarted`/event lists. Verify projection has an explicit no-logical-update value and the send path suppresses it for every message type. Paired runs with identical visible updates assert no hidden-triggered broadcast or frame-count difference.
- [ ] **Durability and recovery:** implement and fault-test `seat_streams(session_id, seat_id, binding_epoch, generation, cursor)`, created at first bind; atomically commit per-recipient cursor UPSERTs with canonical events and binding transitions. Test restart/crash before send, missing/malformed/epoch-mismatched records, higher stored epoch corruption, fresh random generation-token recovery (including rejection of a previously issued generation/cursor pair after a missing-row reinitialization), StateSync re-baseline, and rejection of old `(bindingEpoch,generation,seq)` even when numeric seq equals head. Bind/release/replace/revoke advance epoch; same-binding takeover and token rotation/rollback do not. Recovery never changes binding epoch.
- [ ] **Chat recipient plan and ordering:** share one active-membership predicate (`status = 'active'`) between transactional recipient computation and per-socket `hasCurrentSeat`; derive visibility from the Room state being committed under the single-writer queue and re-verify membership in the transaction. Pass the plan into `writeChat`/`writeTurn`. Socket presence and spotlight selection stay send-time. Delay chat transmission while a synchronous combat frame is ready and assert commit-assigned cursors are attached at dequeue in strict on-wire order; a dequeue-time `hasCurrentSeat`/sendability failure after commit drops the frame as delivery loss without undoing its cursor. Assert transactionally ineligible chat never advances, while membership/socket loss after commit consumes the planned cursor and produces the documented gap/StateSync recovery.
- [ ] **Chat history:** verify entries contain no canonical seq; assign page-local ordinals after visibility/parse filtering and verify the emitted frame count equals the filtered entry count.
- [ ] **StateSync and acknowledgements:** audit all recipient-specific StateSync builders/broadcasts, including presence return and late join. Require `(bindingEpoch,generation,seq)` in StateSync/StateSyncAck, compare ack and required-snapshot gates to that viewer's sent baseline/head, and reject stale/global/wrong-generation acknowledgements.
- [ ] **Reducer and probes:** test gap detection for every advancing discriminant, including all combat frames, `PresenceChanged`, `RoundClosing`, and `SeatCharacterReleased`; dropped frames trigger one resync, hidden-only commits trigger none, duplicates/out-of-order frames are ignored, and StateSync applies before resetting baseline. Run deterministic paired hidden-creature-present/absent probes and compare each viewer's full ordered sequenced and unsequenced frame list. Pin failing-first assertion exactly: `CombatTracker seq delta differs between hidden-creature-present and hidden-creature-absent runs`; attach its failure output from main. Include visible-effect positive control, controller and non-controller seats, repeated candidate cells, and narration-ID projection regression.
- [ ] **Residual/send-path audit:** inventory unsequenced ephemeral frames and document hidden-triggerability and disposition. Coalesce hidden-triggerable frames to visible-update boundaries or name each justified residual and observable information. Track token-rotation-before-SeatAuthenticated-delivery as a separate auth-continuity follow-up. Resolve the duplicate solo-owner-recovery `SeatTakenOver` by removing it or routing it through the normal seat stream; do not emit a global sequence.
- [ ] **Budget and cutover:** run the coordinated server/web/schema single-step cutover with old sockets drained and old clients refreshed before authentication. Verify independent per-seat streams and the existing multi-seat synchronization budget (≤1 s under the agreed load profile); do not add legacy global-seq mode or protocol negotiation.

## Alternatives considered

| Option | Gap detection and reconnect | Ordering | Cost and probe outcome |
|---|---|---|---|
| **A. Dense per-viewer cursor plus canonical event id (chosen)** | Preserves contiguous delivery-gap detection; stale or unverifiable stream generation receives authoritative StateSync, never cursor-driven replay. | One per-seat ordered transmit queue attaches cursor at dequeue. | Small durable stream table and coordinated schema/reducer cutover; hidden event count does not affect cursor values or frame structure. |
| **B. Dummy/no-op padding frames** | Requires replay and client logic for meaningless frames. | Can preserve global order only by adding a frame or padding rule per hidden event/batch. | One dummy per hidden event reveals count; padding adds complexity, traffic, and timing. |
| **C. Opaque cursors and ignore gaps** | Equality detects mismatch but not missing delivery; meaningful loss detection recreates a per-viewer chain. | Opaque values alone provide no ordering. | Either loses resync correctness or becomes option A with extra complexity. |
| **D. Accept and document global sequence** | Existing gap recovery conflates hidden omissions with packet loss. | Keeps canonical ordering on wire. | No migration, but repeated area-aim probes can localize hidden activity from sequence deltas. |

## Consequences and scope

The design preserves canonical append-only event semantics and gives each viewer contiguous delivery-gap detection without a numeric proxy for hidden event volume. It adds durable per-seat cursor/generation state and a coordinated server/web/schema cutover. The remaining timing channel is explicit: a viewer can observe a one-bit distinction between hidden-only and visible commits on that stream through cursor-UPSERT work and frame-presence/latency. This timing residual is out of scope; constant-time dummy UPSERTs are a non-goal. Payload-size, transport batching, and visible legitimate game effects remain observable. A pending chat eligibility check may delay later frames in that seat's ordered queue.

**Size: M.** Expected implementation spans schema/handshake, Room delivery and recovery, gateway, web reducer/client, and focused tests. This docs-only PR changes no production behavior.

**Explicitly out of scope:** changing canonical event sequence or snapshot keys; rewriting historical events; hiding legitimate game mechanics, rolls, visible outcomes, or commit timing; fixing separate movement-preview/rejection, damage, narration, public-reveal, or unpadded-message channels; changing chat/private-round content or projection (except ChatHistory entry sequence semantics); hidden-entity authorization/visibility policy; constant-time dummy UPSERT mitigation. Token rotation committed before `SeatAuthenticated` delivery is an auth-continuity follow-up, not cursor behavior.
