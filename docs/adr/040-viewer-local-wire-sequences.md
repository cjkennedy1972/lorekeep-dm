# ADR-040: Viewer-local wire sequences for concealed events

Status: Proposed · Date: 2026-10-31 · Owner: Sage · Work item: card `44b0fcbc` (board `lorekeep-dm`)

Append-only: this ADR adds a wire-delivery contract. It does not edit ADR-003, ADR-010, ADR-029, ADR-033, ADR-034, or ADR-036.

## Context

The canonical room event log uses one contiguous, persisted `seq` per event. `Room` advances `this.seq` to the last stored event and broadcasts `CombatEvents` after applying a viewer-specific projection. Hidden events are omitted from a viewer's projected payload, but the frame still carries the global room head. Thus a viewer can infer how many committed events were withheld from the difference between visible frame sequences. `TurnResolved` is already excluded from client payloads because its filtered `eventIds` disclose hidden-event count, but its global sequence gap remains (the comment in `Room.announceCombat` explicitly records this residual). The same issue applies to any projected event batch, not just `TurnResolved`.

The client contract makes the gap operationally visible: `apps/web/src/room/reducer.ts` treats a non-contiguous sequence as possible lost delivery and requests resynchronization. Therefore simply allowing gaps or sending global cursors under a new name is not sufficient. A frame's sequence currently serves two distinct purposes: canonical event-log position for the server and contiguous delivery position for the client. Those positions must be separated.

Bastion's review of PR #431 demonstrated a hidden area-resolution case with 9 persisted events when the hidden creature was in the blast and 7 when it was absent, although the acting viewer's projected event bodies matched. Its later review noted that repeated area-aim probes could localize a hidden creature from sequence deltas. PR #432's reviews repeatedly excluded this card; one probe also observed differing sequence values for a hidden-reactor movement. These are residual channels, not regressions introduced by those PRs.

Relevant contracts: ADR-003 makes the server event log append-only and replay-authoritative; ADR-010 assigns sequence-gap recovery to the client; ADR-029 establishes the serialized Room; ADR-034 requires per-viewer omission of hidden entities/events while preserving the canonical log and specifies coalesced hidden-reactor movement; ADR-036 treats reconnect StateSync as authoritative and keeps private projections separate. The narrow invariant is: **for two executions with identical viewer-visible logical updates, the ordered sequenced-frame list (frame type, count, order, and cursor values) is identical.** This closes count and position leakage through sequence metadata and frame boundaries; it does not claim to hide delivery timing, transport batching, payload-size differences, or other side channels listed below.

## Decision

Keep the canonical persisted sequence (`eventSeq`, currently stored `seq`) global, contiguous, and authoritative for event order, snapshots, replay, rewind, and internal event references. Introduce a separate **viewer-local wire sequence** for each authenticated seat delivery stream. Within that stream it advances only for sequenced, viewer-visible logical updates; it is dense, strictly increasing, and never derived directly from the global event number. Internal event ranges may contain multiple canonical events; hidden events do not consume a viewer cursor.

**Sequenced-frame inventory and cursor source.** Every outbound application frame is in the confidentiality comparison, whether or not it has a `seq`. The implementation is a single-step wire/schema cutover: the current schema requires global `seq` on some frames and does not carry binding epochs. The following is the target classification after the schema changes required here:

- **Advances the bound seat stream by one** when sent as a viewer-visible logical update: `ChatMessage`, `ActionQueued`, `RoundOpened`, `RoundActionAccepted`, `RoundActionQueued`, `RoundActionEdited`, `RoundActionWithdrawn`, `RoundClosing`, `RoundResolved`, `RoundCompleted`, `RoundClosedEmpty`, `RoundTimerConfigured`, `TurnTimerConfigured`, `SeatRevoked`, `SeatCharacterBound`, `SeatCharacterReleased`, `SeatTakenOver`, `HostTransferred`, `HostSeatChanged`, `LateJoinRequested`, `LateJoinDenied`, `TableEnded`, `ChatMuteChanged`, `LateJoinApproved`, `SeatClaimRequested`, `SeatClaimApproved`, `SeatClaimDenied`, `SeatClaimExpired`, `RestVoteOpened`, `RestVoteCastNotice`, `RestVoteClosed`, `RestApplied`, `ActionWithdrawn`, `ClarificationRequested`, `TurnThinking`, `RollEvent`, `NarrationChunk`, `NarrationCompleted`, `TurnReverted`, `ToolRejected`, `ContentTierChanged`, `SafetyFlag`, `DeathSaveRequired`, `TpkChoiceRequired`, `SpotlightPrompt`, `CombatTracker`, `ReactionPrompt`, `ReactionPromptOpen`, `CombatOptions`, `CombatEvents`, `CombatEnded`, and persisted `PresenceChanged`. `PresenceChanged` is a viewer-visible logical update and advances each eligible recipient’s viewer cursor; its wire `seq` is never the canonical `event.seq`. `TurnResolved` is a canonical event carried within delivery, not a standalone frame discriminant. Each advancing frame uses the recipient's next viewer-local cursor, assigned after its visibility projection and coalescing.
- **Carries the current bound-seat cursor without advancing it (class (b)):** `StateSync` (authoritative baseline/checkpoint, including presence-return broadcasts), `ChatHistory`, `NarrationHistory`, `SeatPrivateRoundSync`, `Error`, `SeatAuthenticated`, `SeatClaimPending`, and `SeatCharacterBoundPrivate`. These are direct request/handshake/private-seat replies or error responses and never advance the cursor. If an authentication/handshake frame is sent before a viewer stream is bound, it is pre-baseline and does not initialize a cursor. Every `StateSync` is constructed separately for its recipient with that recipient’s current viewer cursor; never broadcast a global head. `ChatHistory` frame `seq` is the current viewer cursor, while each history entry uses a page-local ordinal (or viewer chat cursor), never canonical `events.seq`. `StateSync` re-baselines the client only after its authoritative projection is applied. Snapshot cursor values come from the bound `(seatId, bindingEpoch)` checkpoint, never from the canonical global head.
- **Pre-baseline, not a cursor frame:** `SeatResumeChallenge` is currently serialized with `seq: 0` before a seat stream is bound. That zero is a schema/handshake placeholder only; it MUST NOT enter the stream, initialize or advance a reducer cursor, count as a sequenced frame, or satisfy `StateSyncAck`. The implementation cutover removes `seq` from this pre-baseline message (or otherwise makes it explicitly cursor-less) in the schema.

This list must stay in sync with `ServerMessageSchema`; every new discriminant must be assigned exactly one class before implementation. At every concrete `seq: this.seq`, `seq: room.seq`, helper-constructor, forwarded-event, and no-`seq` app-frame send site, the implementation audit records the discriminant and its class. Cursor source for all sequenced classes and class-(b) frames is the server-bound seat stream; no frame may carry the global head. The cutover changes `ServerMessageSchema` so `PresenceChanged.seq` is a viewer cursor and `Error.seq` is the current viewer cursor (not global); `Error` remains class (b) and does not advance it. Transport-level pings/pongs and close frames are independent of Room commits and are excluded from the application-frame count invariant; they MUST NOT be generated or scheduled per hidden event.

A **logical update** and its frame boundary are defined by viewer-visible state, not by canonical commit count. Before sending sequenced frames, the server MUST coalesce/split updates so that hidden-only events, hidden commit splitting, and hidden prompts cannot change the number, type, or order of sequenced frames observed by a viewer whose visible logical updates are otherwise identical. In particular, hidden events that cause reaction-open/resolve, narration, or `TurnResolved` commits must not introduce or split a viewer frame. Per-commit cursors alone do not satisfy this rule. Assign one increment per viewer-visible logical update after projection/coalescing. **A hidden-only canonical commit emits zero sequenced application frames of any type and zero unsequenced application frames. There are no per-commit exceptions.** A `StateSync` may be sent for an explicit new-seat attach, cursor/epoch mismatch (or unverifiable checkpoint), or the existing presence-return refresh; every such send is built separately for the recipient using that seat’s viewer cursor. It is a recovery/refresh checkpoint, not a hidden-commit notification, and is never emitted once per hidden commit. Frames carrying the current cursor without advancing are class (b): explicit client-request replies (including `StateSync` recovery and `CombatOptions`), per-recipient presence-return `StateSync` refreshes, private auth/seat-binding replies, and `Error` responses. They are never hidden-commit notifications and are covered by the same paired-execution frame-list comparison. A commit whose projection for a viewer is empty emits zero sequenced frames of every type to that viewer, including no class-(b) frames, and zero unsequenced application frames.

Current-code note: `apps/web/src/room/reducer.ts` currently performs contiguous-gap checks for `PresenceChanged` only; most combat and room patch families return without checking `seq`, while `StateSync` ignores a numerically stale snapshot when a room already exists. This ADR requires the implementation to change the reducer so every class-(a) sequenced frame, including `PresenceChanged`, all combat frames (`CombatTracker`, `ReactionPrompt`, `ReactionPromptOpen`, `CombatOptions`, `CombatEvents`, `CombatEnded`, `DeathSaveRequired`, `TpkChoiceRequired`) and room-state frames, participates in the same contiguous cursor check. A missing next cursor sets `needsResync`; the room client observes that transition and sends `Resync`. Duplicate/older frames are ignored. `StateSync` must authoritatively establish the baseline for the current bound epoch rather than be rejected solely because its numeric cursor is lower than the previous epoch’s cursor; `StateSyncAck` is epoch-aware as specified below. `SeatResumeChallenge` is pre-baseline metadata and MUST NOT be passed to this cursor logic. All unsequenced application frames are also subject to hidden-event coalescing and the frame-list oracle below; they are not exempt from count confidentiality merely because they cannot create a sequence gap. The implementation audit MUST inventory every unsequenced ephemeral send path and determine whether hidden events can trigger it directly or indirectly. `PresenceChanged` is not unsequenced; `Error` carries the current viewer cursor as class (b). Hidden-triggerable unsequenced frames MUST be coalesced under the same visible-update boundary rule; if a specific frame cannot be coalesced, the implementation PR must name it as an explicit out-of-scope residual and explain why it is necessary and what information remains observable. No unsequenced frame is implicitly exempt. A checkpoint resets the baseline only after its authoritative projection is applied.

The server retains canonical global event id/sequence internally. Viewer-local sequence is delivery metadata, not an event identifier, ordering source, or persistence key. Cursors **never drive replay**: reconnect/resync sends nothing only when the authenticated viewer cursor equals that viewer's current stream head; any mismatch, absent/unverifiable cursor, or epoch mismatch sends authoritative StateSync. The reconnect and late-join `StateSync` gates and the coupled `sendNarrationHistory` gates MUST compare against the bound viewer stream head, never `this.seq`/global head. Narration history is included only under its existing visibility policy and must not be gated by global-head comparison.

Live delivery filters using the authenticated recipient and visibility/control state captured at the canonical commit boundary; this is not a persisted replay eligibility record. Wire replay is not part of this ADR. If replay is added in the future, it must persist an immutable commit-time delivery-eligibility decision with the canonical event/commit and reuse it, never re-project historical events using current controller/seat state. If that decision or replay material is unavailable or inconsistent, fall back to StateSync; never infer visibility from current control state. Do not add a per-viewer payload history or global-to-viewer cursor map as part of this decision.

A viewer stream is keyed by server-bound `(sessionId, seatId, bindingEpoch)`, never by a client-selected seat/account/socket/cursor. The gateway enforces **one active socket per seat**; a replacement socket closes/removes the prior socket before it is attached. `Room` stores and routes connections in a seat-keyed map. A replacement/reconnect for the same authenticated binding shares that seat epoch and durable cursor; there is never multi-socket fan-out or per-socket cursor reconciliation. The schema cutover adds `bindingEpoch` to `StateSync` and `StateSyncAck`; on both frames `seq` is the viewer-local wire cursor, not the global sequence. `StateSyncAck` is accepted only on the socket bound by the server to the same seat and epoch as the outstanding StateSync, and only when its `(bindingEpoch, seq)` equals the sent baseline. Client-supplied identifiers never choose a stream; echoed epoch/cursor data can only confirm the server-bound one.

On a seat’s first bind, initialize cursor `0` at epoch `1`. The durable seat-binding row contains the epoch; the epoch increments only on a bind, release, replace, or revoke of that seat binding, in the same transaction as that binding change. “Replace” means assigning the seat to a different binding row/account (including `SeatTakenOver` when it changes that binding); gateway socket takeover for the same binding is not a binding replace and does not bump the epoch. Resume-token rotation or rollback is not a binding change and leaves the epoch and cursor untouched; a later reconnect after rollback presents its cursor in the same epoch and follows the normal StateSync-on-mismatch rule. The separate case where a rotated token is committed but delivery fails is an authentication follow-up, not a cursor-epoch mutation. Retain the row/tombstone across release so epochs cannot be silently reset. The stream checkpoint row stores the epoch it belongs to; a cursor from any different epoch is never accepted. StateSync/StateSyncAck carry the binding epoch. A takeover socket within the same epoch inherits the durable cursor and receives StateSync; it does not create another stream.

Cursor-bearing frames are transmitted through one ordered send queue per seat. The durable cursor head is advanced atomically with the canonical event commit as specified below; the frame’s viewer cursor is attached at send time when that frame is dequeued for transmit, so on-wire order is cursor order. For `ChatMessage`, compute recipient eligibility—including the current-seat (`hasCurrentSeat`) check and visibility—inside the canonical commit transaction before any per-recipient cursor UPSERT. Only eligible recipients advance a cursor. `ChatHistory` entries likewise never expose canonical event sequence values. The ordered queue assigns/attaches cursors at dequeue after any remaining async gate; an ineligible recipient never consumes a cursor. If a frame is eligible and committed but subsequently lost because its socket disappears or a send races with disconnect, the next received cursor has a gap and the client requests resync/authoritative StateSync by design. A delayed chat check cannot let a later cursor overtake an earlier transmitted frame.

### Persistence and recovery contract

Use one durable cursor row per seat stream, `room_viewer_stream_cursor(session_id, seat_id, binding_epoch, wire_seq)`, keyed by `(session_id, seat_id)`. The binding epoch is stored on the durable seat-binding row (not merely a resume-token hash/rotation record), not allocated by socket takeover. On first bind the epoch is `1` and cursor is `0`; every bind/release/replace/revoke increments the binding-row epoch and resets the cursor to `0` in the same transaction as that binding change. The cursor row’s epoch must equal the binding row’s epoch; a cursor from another epoch is never accepted. Retain released-seat binding rows so the epoch cannot be reset by seat deletion/recreation.

Each canonical event commit and the stream cursor it advances are atomic: compute the eligible recipient seat set (including current-seat eligibility and visibility) inside the commit transaction before cursor advancement. In the same transaction that commits canonical event rows, issue one UPSERT per eligible recipient whose projection of that commit batch is non-empty, updating that seat’s `wire_seq` and `binding_epoch` in `room_viewer_stream_cursor`. Do not separately checkpoint the cursor. A projection-empty recipient gets no cursor UPSERT and zero frames; a non-empty projection increments its cursor only according to the coalesced viewer-visible logical updates. The transaction also commits any binding/epoch mutation when one is part of the operation. Send frames only after commit. If the transaction fails, publish neither in-memory cursor changes nor frames. A crash or socket loss between commit and send may leave an eligible client’s `lastSeq` behind the durable table; the resulting cursor gap triggers resync and authoritative StateSync, with no replay. Recipients excluded by the transactional eligibility check do not advance.

On restart, load each in-memory cursor from `room_viewer_stream_cursor` and compare its epoch with the durable binding-row epoch. If the cursor row is absent, malformed, or its epoch differs from the binding-row epoch, do not infer a cursor from the Room/global head and do not change the binding epoch. Reinitialize the cursor row for the current binding epoch at cursor `0` (UPSERT in the same transaction as the next canonical commit, or at subscribe before sending StateSync), send authoritative StateSync at that baseline, and have the client re-baseline; the first advancing frame after StateSync carries cursor `1`. If the cursor row epoch is higher than the binding-row epoch, treat it as corruption: perform the same current-epoch reinitialization and emit a structured error log containing the event name only (no identifiers or payload). If reinitialization cannot be confirmed, keep the seat disconnected. A cursor row whose epoch matches the binding row is loaded; a reconnect whose client cursor is behind the durable row still receives StateSync (never replay). A crash after the event/cursor transaction commits but before wire send is safe: the client is simply behind the table and reconnect gets StateSync. Rewind appends canonical events as ADR-003 requires; it never decrements or reuses a viewer cursor.

Do not persist per-viewer event payloads, duplicate histories, or a per-event global-to-viewer mapping. Live delivery evaluates the bound seat's visibility at the commit boundary and persists only the latest atomic checkpoint. The event store is queried by canonical `eventSeq`; cursors never drive wire replay. `StateSyncAck` compares the acknowledged `(bindingEpoch, seq)` against the baseline sent on that bound socket. Late-join snapshot bookkeeping (`recordLateJoinSnapshot`, `lateJoinSnapshotSeqs`, and `requiredSnapshotSeq`) stores and compares the bound viewer's wire baseline, not `this.seq`/global head. The schema cutover changes strict `StateSyncAck` payload from `{ seq }` to `{ seq, bindingEpoch }`; `seq` is the viewer cursor. `StateSync` likewise includes `bindingEpoch` and uses `seq` for that recipient’s viewer cursor. A stale, missing, wrong-epoch, or global-valued StateSyncAck is rejected and the authoritative StateSync is resent; it never unlocks the socket or advances late-join admission.

All sequenced frames are classified above. Frames with no visible logical change carry the current bound-seat cursor only when they are one of the explicitly listed request-scoped snapshots; otherwise they are unsequenced and remain subject to coalescing. No client-visible payload may include `eventSeq`, canonical event ids, hidden-event count, or a global head cursor.
### Compatibility and rollout

Use a **single-step cutover**, shipping server and web together. Do not add protocol negotiation, adoption tracking, or a dual-protocol window: the project is pre-release (`apps/*/package.json` is `0.0.0`; the architecture beta gate is week 23+), and no wire capability/version negotiation exists. Keeping a legacy global-sequence mode would leave the disclosure open for an unbounded period. A dense per-viewer sequence remains compatible with the existing client's `lastSeq + 1` rule; frames with `seq <= lastSeq` remain ignored. A stale or mismatched cursor receives StateSync. Add compatibility tests for the schema and cursor behavior rather than a rollout window. Deployment requirement: publish server and web as one coordinated cutover, drain old sockets, and require old running clients to refresh/reload before seat authentication; send an authoritative StateSync after attach. This ADR does not introduce a second protocol or claim a wire-level negotiation mechanism. An incompatible client must never silently receive global sequence numbers after cutover.

On first viewer-local connection, send StateSync with that seat-epoch cursor baseline. Reconnect with missing, old, corrupt, or wrong-epoch cursor receives StateSync; no historical event-row backfill is needed. Preserve canonical `eventSeq` in the database and all internal joins/snapshots.

### Required tests (implementation acceptance; not part of this docs-only change)

- **Sequenced-frame inventory and probe:** enumerate the actual sequenced discriminants and cursor source from every Room/gateway send path, including all B1-listed frames and reconnect StateSync. Run the same deterministic Room/websocket area attack/aim twice with pinned dice/RNG and identical visible logical outcomes. Capture each viewer's full ordered application-frame list (sequenced and unsequenced) as `(type, count, seq-or-null, body)`; assert byte-identical viewer observations, including frame count and order, while canonical persisted counts/global IDs differ. Explicitly assert hidden-only commits emit zero application frames. The `SeatResumeChallenge seq: 0` handshake placeholder is excluded as pre-baseline metadata, not counted or treated as a cursor. Cover `CombatTracker`, `PresenceChanged`, hidden-reactor `ReactionPromptOpen` to a non-controller, all sequenced room/game frames, and every recipient-specific `StateSync`, including the presence-return broadcast. Assert `Error` carries only the current viewer cursor and never advances it or uses the global head. Assert `ChatHistory` entries use viewer-local ordinals and never contain canonical event sequence values. Repeat candidate cells. Assert timing is excluded (or separately measured); do not infer timing equality from sequence equality. Before the fix, the probe on `main` MUST fail with this exact assertion string: `CombatTracker seq delta differs between hidden-creature-present and hidden-creature-absent runs`. Pin that signature in the test and require the implementation PR to attach the failing-first output; generic `seq differs` is insufficient. Add a visible-creature blast positive control with a differing visible outcome and corresponding allowed frame difference. Run both controller and non-controller seats; prove independent streams.
- **Frame-boundary invariance:** vary only hidden-event count and hidden commit splitting (including reaction prompt open/resolve, TurnResolved write, and narration). With identical viewer-visible logical updates, frame type/count/order and projected bodies must remain identical. A cursor-per-commit implementation alone must fail this test.
- **Ordered transmit / async chat gate:** delay the asynchronous current-seat check for a `ChatMessage` while a synchronous combat frame is ready. Assert that each transmitted cursor-bearing frame receives its cursor only at dequeue and on-wire cursors are strictly increasing in transmit order. Assert an ineligible recipient never consumes a cursor; simulate socket loss after an eligible chat commit and verify the next received cursor gap requests resync/StateSync.
- **Reducer gap correctness:** drop each family of sequenced frame, including every combat type listed in the Decision; `needsResync` is set and exactly one resync is requested. A hidden-only commit creates no cursor gap/resync; duplicates and out-of-order frames are ignored. Checkpoint applies projection then resets baseline.
- **Reconnect/restart and gates:** verify equality with the bound viewer stream head is the sole no-send fast path. Exercise late join, reconnect and resync where hidden-only canonical events committed while disconnected: StateSync/narration-history behavior must not reveal that global delta. Cover `StateSyncAck` and late-join bookkeeping: the strict schema carries `{ seq, bindingEpoch }`, with `seq` the viewer cursor, and acknowledgements must match the bound `(bindingEpoch, seq)` baseline; a stale or global-valued ack is rejected and cannot unlock the socket or satisfy a late-join snapshot. Stale, absent, corrupt, or wrong-epoch cursor gets authoritative StateSync. Cursors never initiate replay.
- **Per-seat isolation / epochs:** simultaneous seats get independent dense streams; client-supplied seat ids/cursors cannot choose a stream. Bind/release/replace/revoke changes start a new durable epoch and force StateSync; replace means reassignment to a different binding row/account, including `SeatTakenOver` only when it changes the binding. Socket takeover for the same binding and resume-token rotation/rollback leave epoch and cursor unchanged, with reconnect handled by the normal StateSync-on-mismatch rule; an old `(epoch,cursor)` cannot be resumed after a binding change. Restart and crash injection between canonical writes/checkpoint attempts prove event+cursor atomicity; an absent, malformed, mismatched, or corrupt cursor row is reinitialized at cursor `0` in the current binding epoch and receives StateSync (a cursor epoch higher than the binding epoch is also logged as a structured error).
- **Commit-time visibility for future replay:** test that a hypothetical replay never makes an event visible because controller state changed after commit. If immutable commit-time eligibility is absent, verify replay falls back to StateSync.
- **Ordering and latency:** concurrent commits across a 2–6-seat room yield monotonic per-seat delivery in canonical order; instrumentation verifies added projection/cursor work keeps existing end-to-end multi-seat synchronization budget at or below 1 s under the project's agreed load profile.
- **Single-cutover compatibility:** compatibility test exercises existing `lastSeq + 1` clients against dense per-viewer sequences, ignores `seq <= lastSeq`, and recovers stale/mismatched cursors by StateSync. No legacy global-seq serving mode or negotiation window remains.
- **Canonical semantics and projection regression:** canonical event replay, snapshots, rewind, redaction, and internal references continue using global event sequence. Add a regression asserting `clientGameState` strips `turnNarrationEvents`, `turnNarrationEventIds`, and `narrationAttempts` from `combatRoom`; `turnNarrationEventIds` must never expose canonical seq values.

## Consequences

Viewer clients retain the ADR-010 gap-detection guarantee after the reducer and schema cutover, without receiving a numeric proxy for withheld event volume. Server persistence remains canonical and append-only; wire ordering is explicitly a projection of that history. The change adds a small per-seat, per-binding-epoch recovery cursor and requires a coordinated single-step server/web/schema cutover. Timing remains an excluded side channel: visible commits perform one per-seat cursor UPSERT per eligible recipient inside the commit transaction, while hidden-only commits skip those UPSERTs, so wall-clock commit/delivery latency can differ. A pending chat eligibility check can also delay later queued frames for that seat. The invariant covers sequence and frame structure, not timing or payload-size equality; visible legitimate game effects remain observable.

## Size and scope

**Size: M (cross-cutting protocol/state migration, no event-row rewrite).** Expected implementation spans schema/handshake, Room delivery and recovery, gateway, web reducer/client, and focused server/web tests. No production behavior changes are included in this ADR PR.

**Explicitly out of scope:** changing canonical database event sequence or snapshot keys; redacting or rewriting historical events; suppressing game mechanics, rolls, visible outcomes, or equalizing event/commit timing; fixing the separate information channels from movement previews/rejections, damage, narration, public reveals, or unpadded message timing; encrypting event cursors; changing chat/private-round message content or projection (the `ChatHistory` sequence field and entry ordinals are in scope); solving hidden-entity authorization or visibility rules; implementing this ADR in the docs-only PR. This ADR covers numeric event-count leakage from sequence/cursor metadata, not all side channels.
