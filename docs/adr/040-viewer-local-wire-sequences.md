# ADR-040: Viewer-local wire sequences for concealed events

Status: Proposed · Date: 2026-10-31 · Owner: Sage · Work item: card `44b0fcbc` (board `lorekeep-dm`)

Append-only: this ADR adds a wire-delivery contract. It does not edit ADR-003, ADR-010, ADR-029, ADR-033, ADR-034, or ADR-036.

## Context

The canonical room event log uses one contiguous, persisted `seq` per event. `Room` advances `this.seq` to the last stored event and broadcasts `CombatEvents` after applying a viewer-specific projection. Hidden events are omitted from a viewer's projected payload, but the frame still carries the global room head. Thus a viewer can infer how many committed events were withheld from the difference between visible frame sequences. `TurnResolved` is already excluded from client payloads because its filtered `eventIds` disclose hidden-event count, but its global sequence gap remains (the comment in `Room.announceCombat` explicitly records this residual). The same issue applies to any projected event batch, not just `TurnResolved`.

The client contract makes the gap operationally visible: `apps/web/src/room/reducer.ts` treats a non-contiguous sequence as possible lost delivery and requests resynchronization. Therefore simply allowing gaps or sending global cursors under a new name is not sufficient. A frame's sequence currently serves two distinct purposes: canonical event-log position for the server and contiguous delivery position for the client. Those positions must be separated.

Bastion's review of PR #431 demonstrated a hidden area-resolution case with 9 persisted events when the hidden creature was in the blast and 7 when it was absent, although the acting viewer's projected event bodies matched. Its later review noted that repeated area-aim probes could localize a hidden creature from sequence deltas. PR #432's reviews repeatedly excluded this card; one probe also observed differing sequence values for a hidden-reactor movement. These are residual channels, not regressions introduced by those PRs.

Relevant contracts: ADR-003 makes the server event log append-only and replay-authoritative; ADR-010 assigns sequence-gap recovery to the client; ADR-029 establishes the serialized Room; ADR-034 requires per-viewer omission of hidden entities/events while preserving the canonical log and specifies coalesced hidden-reactor movement; ADR-036 treats reconnect StateSync as authoritative and keeps private projections separate. The invariant is: **a viewer-visible numeric wire sequence must reveal neither the number nor positions of events withheld from that viewer, and a missing viewer-visible frame must still be detectable.**

## Decision

Keep the canonical persisted sequence (`eventSeq`, currently stored `seq`) global, contiguous, and authoritative for event order, snapshots, replay, rewind, and internal event references. Introduce a separate **viewer-local wire sequence** for each authenticated seat's delivery stream. Within that stream it advances only for sequenced, viewer-visible logical updates; it is dense, strictly increasing, and never derived directly from the global event number. A projected batch may carry one wire sequence while its internal visible event list contains multiple canonical events; hidden events do not consume a viewer's sequence. Unsequenced ephemeral messages remain outside gap detection, as today.

The server retains the canonical global event id/sequence alongside each event internally. Viewer-local sequence is delivery metadata, not an event identifier, ordering source, or persistence key. The server MUST assign it after authorization, filtering, and projection, consistently for live delivery and any replayed event delivery. StateSync is an authoritative checkpoint: it carries the viewer's current wire sequence and resets the client's baseline. Reconnect/resync compares the viewer's client cursor with that viewer's stream head; if equal, the current fast path may remain, and if unequal or unverifiable, send StateSync. StateSync payload contents remain the existing per-viewer projection.

A viewer stream is keyed by stable authenticated seat identity, not socket/account display identity. Seat replacement/reconnect preserves its cursor. A new seat starts a new stream; seat revocation terminates access and does not expose another seat's cursor. A viewer's visibility/control relation is evaluated at commit and is not retroactively used to make previously withheld events visible. Cursor updates and event commits are serialized by the Room mailbox so no two frames race or reorder the stream.

### Persistence and recovery contract

Persist or checkpoint the latest viewer-local cursor with the Room's durable head (one small value per active seat) in the same transactional/serialized progression as canonical events. Do not persist a per-viewer copy of event payloads, duplicate event histories, or a global-to-viewer mapping for every event. The event store continues to be queried by canonical `eventSeq`; the viewer projection is applied during event delivery. If a cursor checkpoint is absent, malformed, or inconsistent on recovery, do not guess from the global head: send StateSync and establish a safe viewer-local baseline. Rewind appends canonical events as ADR-003 requires; it never decrements or reuses a viewer cursor. Account deletion/redaction retains its existing event semantics.

StateSync and all messages currently using `room.seq` as a client cursor must be audited. Frames without a visible state change may carry the current viewer cursor but must not advance it. One committed update delivered to multiple seats may have different wire cursors while referring internally to the same canonical event range. No client-visible payload may include `eventSeq`, canonical event ids, hidden-event count, or a global head cursor.

### Compatibility and rollout

1. **Additive server preparation.** Keep the existing numeric `seq` behavior for legacy clients while adding an explicit negotiated wire protocol version/capability for viewer-local sequences. Do not infer capability from a client's supplied number. New clients send the capability during the existing connection/resume handshake; server validates it and binds the connection to that protocol for its lifetime.
2. **Dual protocol window.** New server supports both modes: legacy clients receive the current global `seq` contract; opted-in clients receive dense viewer-local sequence in the existing client `seq` field. New clients accept either mode, but only apply gap detection to the negotiated viewer-local stream. This preserves old-client behavior and makes the remaining legacy leak explicit during the migration window.
3. **Client adoption and minimum version.** Release the new client first and measure negotiated-seat adoption. Once the minimum supported client version is raised, stop serving legacy global sequence to clients. Do not claim the confidentiality invariant is fully deployed while legacy mode remains available. If an old client cannot be supported after the cutoff, require refresh/upgrade and send an authoritative StateSync rather than silently changing its sequence semantics.
4. **Recovery/cutover.** On first viewer-local connection, send StateSync with that seat's cursor baseline. Reconnect with missing/old cursor receives StateSync; no migration/backfill of historical event rows is needed. Preserve canonical `eventSeq` in the database and all internal joins/snapshots.

### Required tests (implementation acceptance; not part of this docs-only change)

- **Hidden-event-count probe, must fail on current `main`:** run the same real Room/websocket area attack/aim twice, with identical viewer-visible state and event bodies, changing only whether a hidden creature occupies the blast. Assert viewer-visible `seq` deltas and wire envelopes are identical under the new protocol while canonical persisted event counts/global IDs differ. The probe must first be run on `origin/main` and fail specifically because current global `seq` deltas differ (Bastion observed 9 vs 7 events in #431); save that failing-first evidence with implementation review. Repeat probes across candidate aim positions and assert the viewer cannot infer the hidden creature's cell from cursor differences. Include a visible-creature positive control where the visible outcome and sequence may legitimately differ.
- **Gap correctness:** a missing viewer-visible logical update (inject/drop a wire frame) sets `needsResync` and requests one resync; a withheld hidden event does not create a gap or resync; duplicate and out-of-order viewer frames remain ignored.
- **Reconnect/restart:** persist events and cursor, disconnect, recover Room, and verify a matching per-seat cursor does not skip visible updates; a stale, absent, or corrupt cursor produces an authoritative StateSync with a consistent baseline. Exercise newly connected and resumed seats.
- **Per-seat isolation:** simultaneous seats receive independent dense streams, including hidden controller/non-controller projection, and neither cursor can be used to read another seat's event history. Seat revocation/rebinding and newly admitted seats start or retain only their authorized stream.
- **Ordering and multi-seat latency:** concurrent commits across a 2–6-seat room yield monotonic per-seat delivery in canonical order; instrumentation verifies the added projection/cursor work keeps the existing end-to-end multi-seat synchronization budget at or below 1 s under the project’s agreed load profile.
- **Compatibility:** old client/global-seq negotiation retains current behavior; new client against legacy server and legacy client against dual-mode server recover via StateSync; unnegotiated clients cannot opt into a cursor by forging client numeric `seq`.
- **Replay and snapshots:** canonical event replay, snapshots, rewind, redaction, and existing event references continue using global event sequence; per-viewer cursor recovery never rewrites or reorders canonical records.

## Consequences

Viewer clients retain the gap-detection guarantee from ADR-010 without receiving a numeric proxy for withheld event volume. Server persistence remains canonical and append-only; wire ordering is explicitly a projection of that history. The change adds a small per-seat recovery cursor and a negotiated compatibility period. During dual mode, legacy clients retain the known disclosure until the supported-client cutoff; rollout tracking must report that residual honestly. The design does not hide that visible, legitimately disclosed events occurred, nor does it equalize frame timing or total payload size where those are already visible through public game effects.

## Size and scope

**Size: M (cross-cutting protocol/state migration, no event-row rewrite).** Expected implementation spans schema/handshake, Room delivery and recovery, gateway, web reducer/client, and focused server/web tests. No production behavior changes are included in this ADR PR.

**Explicitly out of scope:** changing canonical database event sequence or snapshot keys; redacting or rewriting historical events; suppressing game mechanics, rolls, visible outcomes, or event timing; fixing the separate information channels from movement previews/rejections, damage, narration, public reveals, or unpadded message timing; encrypting event cursors; changing chat/private-round projections; solving hidden-entity authorization or visibility rules; implementing this ADR in the docs-only PR. This ADR covers numeric event-count leakage from sequence/cursor metadata, not all side channels.
