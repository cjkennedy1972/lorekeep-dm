# ADR-040: Viewer-local wire sequences for concealed events

Status: Proposed · Date: 2026-10-31 · Owner: Sage · Work item: card `44b0fcbc` (board `lorekeep-dm`)

Append-only: this ADR adds a wire-delivery contract. It does not edit ADR-003, ADR-010, ADR-029, ADR-033, ADR-034, or ADR-036.

## Context

The canonical room event log uses one contiguous, persisted `seq` per event. `Room` advances `this.seq` to the last stored event and broadcasts `CombatEvents` after applying a viewer-specific projection. Hidden events are omitted from a viewer's projected payload, but the frame still carries the global room head. Thus a viewer can infer how many committed events were withheld from the difference between visible frame sequences. `TurnResolved` is already excluded from client payloads because its filtered `eventIds` disclose hidden-event count, but its global sequence gap remains (the comment in `Room.announceCombat` explicitly records this residual). The same issue applies to any projected event batch, not just `TurnResolved`.

The client contract makes the gap operationally visible: `apps/web/src/room/reducer.ts` treats a non-contiguous sequence as possible lost delivery and requests resynchronization. Therefore simply allowing gaps or sending global cursors under a new name is not sufficient. A frame's sequence currently serves two distinct purposes: canonical event-log position for the server and contiguous delivery position for the client. Those positions must be separated.

Bastion's review of PR #431 demonstrated a hidden area-resolution case with 9 persisted events when the hidden creature was in the blast and 7 when it was absent, although the acting viewer's projected event bodies matched. Its later review noted that repeated area-aim probes could localize a hidden creature from sequence deltas. PR #432's reviews repeatedly excluded this card; one probe also observed differing sequence values for a hidden-reactor movement. These are residual channels, not regressions introduced by those PRs.

Relevant contracts: ADR-003 makes the server event log append-only and replay-authoritative; ADR-010 assigns sequence-gap recovery to the client; ADR-029 establishes the serialized Room; ADR-034 requires per-viewer omission of hidden entities/events while preserving the canonical log and specifies coalesced hidden-reactor movement; ADR-036 treats reconnect StateSync as authoritative and keeps private projections separate. The narrow invariant is: **for two executions with identical viewer-visible logical updates, the ordered sequenced-frame list (frame type, count, order, and cursor values) is identical.** This closes count and position leakage through sequence metadata and frame boundaries; it does not claim to hide delivery timing, transport batching, payload-size differences, or other side channels listed below.

## Decision

Keep the canonical persisted sequence (`eventSeq`, currently stored `seq`) global, contiguous, and authoritative for event order, snapshots, replay, rewind, and internal event references. Introduce a separate **viewer-local wire sequence** for each authenticated seat delivery stream. Within that stream it advances only for sequenced, viewer-visible logical updates; it is dense, strictly increasing, and never derived directly from the global event number. Internal event ranges may contain multiple canonical events; hidden events do not consume a viewer cursor.

**Sequenced-frame inventory and cursor source.** Every outbound application frame is in the confidentiality comparison, whether or not it has a `seq`. For the current `ServerMessage` schema, the classification is:

- **Advances the bound seat stream by one** when sent as a viewer-visible logical update: `ChatMessage`, `ActionQueued`, `RoundOpened`, `RoundActionAccepted`, `RoundActionQueued`, `RoundActionEdited`, `RoundActionWithdrawn`, `RoundClosing`, `RoundResolved`, `RoundCompleted`, `RoundClosedEmpty`, `RoundTimerConfigured`, `TurnTimerConfigured`, `SeatRevoked`, `SeatCharacterBound`, `SeatCharacterReleased`, `SeatTakenOver`, `HostTransferred`, `HostSeatChanged`, `LateJoinRequested`, `LateJoinDenied`, `TableEnded`, `ChatMuteChanged`, `LateJoinApproved`, `SeatClaimRequested`, `SeatClaimApproved`, `SeatClaimDenied`, `SeatClaimExpired`, `SeatAuthenticated`, `SeatClaimPending`, `RestVoteOpened`, `RestVoteCastNotice`, `RestVoteClosed`, `RestApplied`, `ActionWithdrawn`, `ClarificationRequested`, `TurnThinking`, `RollEvent`, `NarrationChunk`, `NarrationCompleted`, `TurnReverted`, `ToolRejected`, `ContentTierChanged`, `SafetyFlag`, `DeathSaveRequired`, `TpkChoiceRequired`, `SpotlightPrompt`, `SeatCharacterBoundPrivate`, `CombatTracker`, `ReactionPrompt`, `ReactionPromptOpen`, `CombatOptions`, `CombatEvents`, `CombatEnded`. `PresenceChanged` and `Error` are unsequenced, cursor-less frames (class (c), below), not cursor-advancing frames. `TurnResolved` is a canonical event carried within delivery, not a standalone frame discriminant. Each advancing frame uses the recipient's next viewer-local cursor, assigned after its visibility projection and coalescing.
- **Carries the current bound-seat cursor without advancing it:** `StateSync` (authoritative baseline/checkpoint), `ChatHistory`, `NarrationHistory`, and `SeatPrivateRoundSync` (request-scoped snapshots). `StateSync` resets the client baseline only after its projection has been applied. Snapshot cursor values come from the bound `(seatId, bindingEpoch)` checkpoint, never from the canonical global head.
- **Unsequenced, cursor-less frames:** `PresenceChanged` and `Error`. Their send paths do not carry or consume a viewer cursor; they are subject to the unsequenced-frame audit and coalescing/residual rule below.
- **Pre-baseline, not a cursor frame:** `SeatResumeChallenge` is currently serialized with `seq: 0` before a seat stream is bound. That zero is a schema/handshake placeholder only; it MUST NOT enter the stream, initialize or advance a reducer cursor, count as a sequenced frame, or satisfy `StateSyncAck`. The client handles it as pre-baseline handshake metadata. The implementation may remove the placeholder field when the schema is revised.

This list must stay in sync with `ServerMessageSchema`; every new discriminant must be assigned exactly one class before implementation. At every concrete `seq: this.seq`, `seq: room.seq`, helper-constructor, forwarded-event, and no-`seq` app-frame send site, the implementation audit records the discriminant and its class. Cursor source for all sequenced classes is the server-bound seat checkpoint; no frame may carry the global head. Transport-level pings/pongs and close frames are independent of Room commits and are excluded from the application-frame count invariant; they MUST NOT be generated or scheduled per hidden event.

A **logical update** and its frame boundary are defined by viewer-visible state, not by canonical commit count. Before sending sequenced frames, the server MUST coalesce/split updates so that hidden-only events, hidden commit splitting, and hidden prompts cannot change the number, type, or order of sequenced frames observed by a viewer whose visible logical updates are otherwise identical. In particular, hidden events that cause reaction-open/resolve, narration, or `TurnResolved` commits must not introduce or split a viewer frame. Per-commit cursors alone do not satisfy this rule. Assign one increment per viewer-visible logical update after projection/coalescing. **A hidden-only canonical commit emits zero sequenced application frames of any type and zero unsequenced application frames. There are no per-commit exceptions.** A `StateSync` may be sent only for an explicit new-seat attach or a cursor/epoch mismatch (or unverifiable checkpoint); it is a viewer-requested recovery checkpoint, not a hidden-commit notification, and is not emitted once per hidden commit. Frames carrying the current cursor without advancing are allowed only as direct replies to an explicit client request (including `StateSync` recovery and `CombatOptions` replies); they are class (b), never hidden-commit notifications, and are covered by the same paired-execution frame-list comparison. A commit whose projection for a viewer is empty emits zero sequenced frames of every type to that viewer, including no class-(b) frames, and zero unsequenced application frames.

The web reducer MUST apply contiguous-gap detection to every sequenced frame type, including all combat frames (`CombatTracker`, `ReactionPrompt`, `ReactionPromptOpen`, `CombatOptions`, `CombatEvents`, `CombatEnded`, `DeathSaveRequired`, `TpkChoiceRequired`) and room-state frames. A missing next cursor sets `needsResync` and requests resync; duplicate/older frames remain ignored. `SeatResumeChallenge` is pre-baseline metadata and MUST NOT be passed to this cursor logic. All unsequenced application frames are also subject to hidden-event coalescing and the frame-list oracle below; they are not exempt from count confidentiality merely because they cannot create a sequence gap. The implementation audit MUST inventory every unsequenced ephemeral send path, including cursor-less `PresenceChanged` and `Error`, and determine whether hidden events can trigger it directly or indirectly. Hidden-triggerable unsequenced frames MUST be coalesced under the same visible-update boundary rule; if a specific frame cannot be coalesced, the implementation PR must name it as an explicit out-of-scope residual and explain why it is necessary and what information remains observable. No unsequenced frame is implicitly exempt. A checkpoint resets the baseline only after its authoritative projection is applied.

The server retains canonical global event id/sequence internally. Viewer-local sequence is delivery metadata, not an event identifier, ordering source, or persistence key. Cursors **never drive replay**: reconnect/resync sends nothing only when the authenticated viewer cursor equals that viewer's current stream head; any mismatch, absent/unverifiable cursor, or epoch mismatch sends authoritative StateSync. The reconnect and late-join `StateSync` gates and the coupled `sendNarrationHistory` gates MUST compare against the bound viewer stream head, never `this.seq`/global head. Narration history is included only under its existing visibility policy and must not be gated by global-head comparison.

Live delivery filters using the authenticated recipient and visibility/control state captured at the canonical commit boundary; this is not a persisted replay eligibility record. Wire replay is not part of this ADR. If replay is added in the future, it must persist an immutable commit-time delivery-eligibility decision with the canonical event/commit and reuse it, never re-project historical events using current controller/seat state. If that decision or replay material is unavailable or inconsistent, fall back to StateSync; never infer visibility from current control state. Do not add a per-viewer payload history or global-to-viewer cursor map as part of this decision.

A viewer stream is keyed by server-bound `(sessionId, seatId, bindingEpoch)`, never by a client-selected seat/account/socket/cursor. The gateway enforces **one active socket per seat**; a replacement socket closes/removes the prior socket before it is attached. `Room` stores and routes connections in a seat-keyed map. A replacement/reconnect for the same authenticated binding shares that seat epoch and durable cursor; there is never multi-socket fan-out or per-socket cursor reconciliation. A `StateSyncAck` is accepted only on the socket bound by the server to the same seat and epoch as the outstanding StateSync, and only when its `(bindingEpoch, wireSeq)` equals the sent baseline. Client-supplied identifiers never choose a stream; echoed epoch/cursor data can only confirm the server-bound one.

On a seat’s first bind, initialize cursor `0` at epoch `1`. The durable seat-binding row contains the epoch; the epoch increments only on a bind, release, replace, or revoke of that seat binding, in the same transaction as that binding change. Resume-token rotation or rollback is not a binding change and leaves the epoch and cursor untouched; a later reconnect after rollback presents its cursor in the same epoch and follows the normal StateSync-on-mismatch rule. Retain the row/tombstone across release so epochs cannot be silently reset. The stream checkpoint row stores the epoch it belongs to; a cursor from any different epoch is never accepted. StateSync/StateSyncAck carry the binding epoch. A takeover socket within the same epoch inherits the durable cursor and receives StateSync; it does not create another stream.

Cursor-bearing frames are transmitted through one ordered send queue per seat. The durable cursor head is advanced atomically with the canonical event commit as specified below; the frame’s viewer cursor is attached at send time when that frame is dequeued for transmit, so on-wire order is cursor order. For `ChatMessage` and `ChatHistory`, run the asynchronous current-seat/database check before assigning or consuming a cursor and before placing a passing chat frame into the transmit queue. A chat frame dropped by that check never consumes a cursor. Thus a delayed chat check cannot let an already-ready room/combat frame be sent with a later cursor and then be followed by an older chat cursor.

### Persistence and recovery contract

Use one durable cursor row per seat stream, `room_viewer_stream_cursor(session_id, seat_id, binding_epoch, wire_seq)`, keyed by `(session_id, seat_id)`. The durable seat-binding row separately stores its epoch. On first bind the epoch is `1` and cursor is `0`; every bind/release/replace/revoke increments the binding-row epoch and resets the cursor to `0` in the same transaction as that binding change. The cursor row’s epoch must equal the binding row’s epoch; a cursor from another epoch is never accepted. Retain released-seat binding rows so the epoch cannot be reset by seat deletion/recreation.

Each canonical event commit and the stream cursor it advances are atomic: in the same database transaction that commits canonical event rows, issue one UPSERT per recipient whose projection of that commit batch is non-empty, updating that seat’s `wire_seq` and `binding_epoch` in `room_viewer_stream_cursor`. Do not separately checkpoint the cursor. A projection-empty recipient gets no cursor UPSERT and zero frames; a non-empty projection increments its cursor only according to the coalesced viewer-visible logical updates. The transaction also commits any binding/epoch mutation when one is part of the operation. Send frames only after commit. If the transaction fails, publish neither in-memory cursor changes nor frames. A crash between commit and send leaves the client `lastSeq` behind the durable table; reconnect detects the stale cursor and sends authoritative StateSync, with no replay.

On restart, load each in-memory cursor from `room_viewer_stream_cursor` and compare its epoch with the durable binding-row epoch. If the cursor row is absent, malformed, or its epoch differs from the binding-row epoch, do not infer a cursor from the Room/global head and do not change the binding epoch. Reinitialize the cursor row for the current binding epoch at cursor `0` (UPSERT in the same transaction as the next canonical commit, or at subscribe before sending StateSync), send authoritative StateSync at that baseline, and have the client re-baseline; the first advancing frame after StateSync carries cursor `1`. If the cursor row epoch is higher than the binding-row epoch, treat it as corruption: perform the same current-epoch reinitialization and emit a structured error log containing the event name only (no identifiers or payload). If reinitialization cannot be confirmed, keep the seat disconnected. A cursor row whose epoch matches the binding row is loaded; a reconnect whose client cursor is behind the durable row still receives StateSync (never replay). A crash after the event/cursor transaction commits but before wire send is safe: the client is simply behind the table and reconnect gets StateSync. Rewind appends canonical events as ADR-003 requires; it never decrements or reuses a viewer cursor.

Do not persist per-viewer event payloads, duplicate histories, or a per-event global-to-viewer mapping. Live delivery evaluates the bound seat's visibility at the commit boundary and persists only the latest atomic checkpoint. The event store is queried by canonical `eventSeq`; cursors never drive wire replay. `StateSyncAck` compares the acknowledged `(bindingEpoch, wireSeq)` against the baseline sent on that bound socket. Late-join snapshot bookkeeping (`recordLateJoinSnapshot`, `lateJoinSnapshotSeqs`, and `requiredSnapshotSeq`) stores and compares the bound viewer's wire baseline, not `this.seq`/global head. A stale, missing, wrong-epoch, or global-valued StateSyncAck is rejected and the authoritative StateSync is resent; it never unlocks the socket or advances late-join admission.

All sequenced frames are classified above. Frames with no visible logical change carry the current bound-seat cursor only when they are one of the explicitly listed request-scoped snapshots; otherwise they are unsequenced and remain subject to coalescing. No client-visible payload may include `eventSeq`, canonical event ids, hidden-event count, or a global head cursor.
### Compatibility and rollout

Use a **single-step cutover**, shipping server and web together. Do not add protocol negotiation, adoption tracking, or a dual-protocol window: the project is pre-release (`apps/*/package.json` is `0.0.0`; the architecture beta gate is week 23+), and no wire capability/version negotiation exists. Keeping a legacy global-sequence mode would leave the disclosure open for an unbounded period. A dense per-viewer sequence remains compatible with the existing client's `lastSeq + 1` rule; frames with `seq <= lastSeq` remain ignored. A stale or mismatched cursor receives StateSync. Add a compatibility test for this behavior rather than a rollout window. Deployment requirement: publish server and web as one coordinated cutover, drain old sockets, and require old running clients to refresh/reload before seat authentication; send an authoritative StateSync after attach. This ADR does not introduce a second protocol or claim a wire-level negotiation mechanism. An incompatible client must never silently receive global sequence numbers after cutover.

On first viewer-local connection, send StateSync with that seat-epoch cursor baseline. Reconnect with missing, old, corrupt, or wrong-epoch cursor receives StateSync; no historical event-row backfill is needed. Preserve canonical `eventSeq` in the database and all internal joins/snapshots.

### Required tests (implementation acceptance; not part of this docs-only change)

- **Sequenced-frame inventory and probe:** enumerate the actual sequenced discriminants and cursor source from every Room/gateway send path, including all B1-listed frames and reconnect StateSync. Run the same deterministic Room/websocket area attack/aim twice with pinned dice/RNG and identical visible logical outcomes. Capture each viewer's full ordered application-frame list (sequenced and unsequenced) as `(type, count, seq-or-null, body)`; assert byte-identical viewer observations, including frame count and order, while canonical persisted counts/global IDs differ. Explicitly assert hidden-only commits emit zero application frames. The `SeatResumeChallenge seq: 0` handshake placeholder is excluded as pre-baseline metadata, not counted or treated as a cursor. Cover `CombatTracker`, hidden-reactor `ReactionPromptOpen` to a non-controller, all sequenced room/game frames, and StateSync on reconnect mid-turn. Repeat candidate cells. Assert timing is excluded (or separately measured); do not infer timing equality from sequence equality. Before the fix, the probe on `main` MUST fail with this exact assertion string: `CombatTracker seq delta differs between hidden-creature-present and hidden-creature-absent runs`. Pin that signature in the test and require the implementation PR to attach the failing-first output; generic `seq differs` is insufficient. Add a visible-creature blast positive control with a differing visible outcome and corresponding allowed frame difference. Run both controller and non-controller seats; prove independent streams.
- **Frame-boundary invariance:** vary only hidden-event count and hidden commit splitting (including reaction prompt open/resolve, TurnResolved write, and narration). With identical viewer-visible logical updates, frame type/count/order and projected bodies must remain identical. A cursor-per-commit implementation alone must fail this test.
- **Ordered transmit / async chat gate:** delay the asynchronous current-seat check for a `ChatMessage`/`ChatHistory` while a synchronous combat frame is ready. Assert that each transmitted cursor-bearing frame receives its cursor only at dequeue, on-wire cursors are strictly increasing in transmit order, and a chat frame dropped by the check consumes no cursor.
- **Reducer gap correctness:** drop each family of sequenced frame, including every combat type listed in the Decision; `needsResync` is set and exactly one resync is requested. A hidden-only commit creates no cursor gap/resync; duplicates and out-of-order frames are ignored. Checkpoint applies projection then resets baseline.
- **Reconnect/restart and gates:** verify equality with the bound viewer stream head is the sole no-send fast path. Exercise late join, reconnect and resync where hidden-only canonical events committed while disconnected: StateSync/narration-history behavior must not reveal that global delta. Cover `StateSyncAck` and late-join bookkeeping: acknowledgements must match the bound `(bindingEpoch, wireSeq)` baseline; a stale or global-valued ack is rejected and cannot unlock the socket or satisfy a late-join snapshot. Stale, absent, corrupt, or wrong-epoch cursor gets authoritative StateSync. Cursors never initiate replay.
- **Per-seat isolation / epochs:** simultaneous seats get independent dense streams; client-supplied seat ids/cursors cannot choose a stream. Bind/release/replace/revoke changes start a new durable epoch and force StateSync; resume-token rotation or rollback leaves epoch and cursor unchanged, with reconnect handled by the normal StateSync-on-mismatch rule; an old `(epoch,cursor)` cannot be resumed after a binding change. Restart and crash injection between canonical writes/checkpoint attempts prove event+cursor atomicity; an absent, malformed, mismatched, or corrupt cursor row is reinitialized at cursor `0` in the current binding epoch and receives StateSync (a cursor epoch higher than the binding epoch is also logged as a structured error).
- **Commit-time visibility for future replay:** test that a hypothetical replay never makes an event visible because controller state changed after commit. If immutable commit-time eligibility is absent, verify replay falls back to StateSync.
- **Ordering and latency:** concurrent commits across a 2–6-seat room yield monotonic per-seat delivery in canonical order; instrumentation verifies added projection/cursor work keeps existing end-to-end multi-seat synchronization budget at or below 1 s under the project's agreed load profile.
- **Single-cutover compatibility:** compatibility test exercises existing `lastSeq + 1` clients against dense per-viewer sequences, ignores `seq <= lastSeq`, and recovers stale/mismatched cursors by StateSync. No legacy global-seq serving mode or negotiation window remains.
- **Canonical semantics and projection regression:** canonical event replay, snapshots, rewind, redaction, and internal references continue using global event sequence. Add a regression asserting `clientGameState` strips `turnNarrationEvents`, `turnNarrationEventIds`, and `narrationAttempts` from `combatRoom`; `turnNarrationEventIds` must never expose canonical seq values.

## Consequences

Viewer clients retain the gap-detection guarantee from ADR-010 without receiving a numeric proxy for withheld event volume. Server persistence remains canonical and append-only; wire ordering is explicitly a projection of that history. The change adds a small per-seat, per-binding-epoch recovery cursor and requires a coordinated single-step server/web cutover. The narrow invariant covers sequence and sequenced-frame structure, not delivery timing or other public game side channels. The design does not hide that visible, legitimately disclosed events occurred, nor does it equalize frame timing or total payload size where those are already visible through public game effects.

## Size and scope

**Size: M (cross-cutting protocol/state migration, no event-row rewrite).** Expected implementation spans schema/handshake, Room delivery and recovery, gateway, web reducer/client, and focused server/web tests. No production behavior changes are included in this ADR PR.

**Explicitly out of scope:** changing canonical database event sequence or snapshot keys; redacting or rewriting historical events; suppressing game mechanics, rolls, visible outcomes, or event timing; fixing the separate information channels from movement previews/rejections, damage, narration, public reveals, or unpadded message timing; encrypting event cursors; changing chat/private-round projections; solving hidden-entity authorization or visibility rules; implementing this ADR in the docs-only PR. This ADR covers numeric event-count leakage from sequence/cursor metadata, not all side channels.
